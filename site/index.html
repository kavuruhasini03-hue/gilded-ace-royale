♦Model: forecasting daily floor coin-in

Both forecasts were fit on January–April only, then frozen and scored on the 61 May–June days they had never seen. The model uses weekday averages plus ridge-penalized flags for announced events and federal holidays. An event counts only if it was announced before the day, so nothing from the future leaks in. The baseline is the constant January–April daily mean.

Predictions vs. actuals

The shaded area is the holdout. Gold = weekday + event model, red dashed = constant baseline, grey = actual.

Holdout bias by weekday

Average actual minus forecast, May–June. Bars near zero mean no recurring bias.

Decision it changes: The weekday model gives the expected value of each operating hour. We priced the technician-shift packages against it ($11,520 each): even on the busiest weekend nights, recovering the downtime wouldn't cover a 30-day package in July. So the forecast moved the tech shift from "fund" to "don't fund", and the money stays in the reserve.

♣How we measured it

The 4-L bridge

Luck = house win − theoretical win, scaled to a z-score using each game's payout variance.
Lineup = the config's median theo per available hour vs. the floor median.
Location = the zone's typical rate relative to config peers.
Leak = scheduled-but-unavailable hours, valued at the machine's expected rate.
Machine-specific = whatever is left over: actual theo vs. the zone-adjusted config expectation.

Pipeline

The full analysis runs as a Databricks medallion pipeline (bronze → silver → gold, 30+ SQL models) with bootstrap intervals, a ridge forecast logged in MLflow, and a seven-page Databricks AI/BI dashboard. This public site recomputes the core 4-L numbers from the released parquet files with DuckDB, so it may differ slightly from the gold tables, which also use bootstrap intervals and occupancy-weighted downtime.
